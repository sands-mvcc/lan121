Elect the Root, Block the Loop, Build the VLANs

This is Layer 2 engineering with your hands on the wheel. First the math: elect a root bridge from real priority and MAC values, compute root path costs from link speeds, and assign every port its role — including the one STP must block. Then the failure drill: predict what happens when the active path dies, and cut the link in a live topology widget to check yourself. Finally, the build: create VLANs, name them, assign access ports, and bring up an 802.1Q trunk in a real command-line simulator that checks off each milestone as your commands land. 1.1Which switch is elected root bridge?
1.2 Why does that switch win?
Answer: Bridge ID = priority + MAC, compared lowest-wins. With every priority at the default 32768, SW2's 00:0C:… is numerically lowest. Note the trap: default elections crown the switch with the OLDEST MAC — often your oldest hardware.
1.3An engineer runs spanning-tree vlan 1 priority 24576 on SW4. Now which switch is root?
1.4 What is the design best practice this demonstrates?
Answer: Priority beats MAC, so setting the core lower (e.g., 24576 or 4096) makes the topology deterministic. An accidental root in a closet switch drags all traffic through the slowest part of the network.

4 PTSNOT GRADED
3.1 What is the correct order of classic 802.1D port states on the way to forwarding?
Answer: Blocking → Listening → Learning → Forwarding (plus Disabled) — 30–50 seconds of caution before passing traffic.
3.2 What is RSTP's (802.1w) headline improvement?
Answer: Rapid Spanning Tree collapses the state machine and adds proposal/agreement handshakes — failover in seconds. It's the default on modern switches.
3.3 Why enable PortFast on ports facing PCs and printers?
Answer: A PC can't create a loop by itself, so edge ports may safely skip the states — fixing "DHCP fails at boot" complaints caused by STP's delay.
3.4 A PortFast port protected by BPDU Guard receives a BPDU (someone plugged in a switch). What happens?
Answer: BPDU Guard err-disables the port the instant a switch appears where only an end device should be — protecting your topology from rogue switches and accidental loops. (You met err-disabled in Lesson 8's port states.)
4 PTSNOT GRADED

You're designing for a small campus: Sales staff, guest Wi-Fi, and IP phones sharing ports with PCs. Make the calls a network engineer would make.

4.1 Why put Sales and Guest traffic in separate VLANs on the same switch?
Answer: Segmentation = separate broadcast domains + a routed chokepoint for ACLs/firewalls. Same hardware, isolated traffic.
4.2 Best practice for the NATIVE VLAN on your 802.1Q trunks?
Answer: The native VLAN rides untagged; leaving it on the default VLAN 1 enables VLAN-hopping tricks (Lesson 7), and a mismatch leaks traffic between VLANs. Dedicated, unused, and matched.
4.3 The IP phones share ports with PCs. What's the standard solution?
Answer: The voice VLAN is a purpose-built second VLAN on an access port: the phone tags its traffic, the PC stays untagged, and QoS can prioritize calls.
4.4 Sales (VLAN 10) needs to reach a printer in VLAN 20. What does that require?
Answer: Crossing VLANs is routing, full stop. Lesson 3's SVIs or Lesson 4's router-on-a-stick subinterfaces — either way, a Layer 3 hop where policy can live.

All three links below are 1 Gbps; SW1 is root, and STP has blocked SW3's port on the SW2–SW3 segment. Answer the three predictions first, then use the button to fail the SW1–SW3 link and check yourself.

🧠Topology healthy: SW3 reaches the root directly; its port toward SW2 is blocked to break the loop.
6.1 PREDICT: when the SW1–SW3 link fails, what does STP do?
Answer: That standby port is the entire reason STP blocks instead of disabling: the redundant path is held in reserve and activated on failure. Cut the link above and watch exactly this.
6.2 PREDICT: with classic 802.1D, roughly how long is SW3 cut off during that transition?
Answer: The classic state machine costs 30–50 seconds of outage — which is precisely why RSTP (seconds) is the modern default. Users notice 45 seconds.
6.3 After failover, SW3's path to the root is…
Answer: The formerly blocked SW2–SW3 segment is now the working route: SW3 → SW2 → SW1. Redundancy preserved, loop still impossible.
