Ethernet Hubs

Understanding legacy physical layer devices and their operational characteristics

Purpose and Characteristics

Ethernet hubs are simple Layer 1 devices that operate as multiport repeaters. They receive electrical signals on one port and regenerate them out all other ports, creating a single collision domain for all connected devices.

OSI Layer
Layer 1 (Physical)
Collision Domains
Single for all ports
Broadcast Domains
Single domain
Duplex Mode
Half-duplex only
Intelligence Level
No MAC learning
Modern Usage
Obsolete technology

Hub Types and Implementation

Hub Type Signal Processing Features Use Cases
Passive Hub No amplification Simple signal distribution Basic connectivity (legacy)
Active Hub Signal regeneration Extended range capability Longer cable runs
Smart Hub Enhanced processing SNMP, stacking, basic VLANs Managed environments

Why Hubs Became Obsolete

Performance Issues: All connected devices share the total bandwidth and operate in a single collision domain. As network usage increases, collision frequency rises, dramatically reducing effective throughput.

Security Vulnerabilities: All traffic is visible to all connected devices, making packet capture and eavesdropping trivial for any connected device.

Scalability Limitations: Half-duplex operation and shared collision domains make hubs unsuitable for modern network demands.

Network Switches

Intelligent Layer 2 devices for efficient frame forwarding and network segmentation

Core Functionality

Switches operate at Layer 2 of the OSI model, making intelligent forwarding decisions based on MAC addresses. They learn and store MAC addresses in a dynamic table, forwarding frames only to the intended recipient port.

Essential configuration steps for enterprise managed switches:

! Enter privileged mode and global configuration Switch> enable Switch# configure terminal ! Set hostname and security parameters Switch(config)# hostname CoreSwitch-01 CoreSwitch-01(config)# enable secret Str0ngP@ssw0rd! ! Configure management VLAN interface CoreSwitch-01(config)# interface vlan1 CoreSwitch-01(config-if)# ip address 192.168.1.10 255.255.255.0 CoreSwitch-01(config-if)# no shutdown CoreSwitch-01(config-if)# exit ! Set default gateway for management CoreSwitch-01(config)# ip default-gateway 192.168.1.1 ! Configure console access CoreSwitch-01(config)# line console 0 CoreSwitch-01(config-line)# password Cons0le123! CoreSwitch-01(config-line)# login CoreSwitch-01(config-line)# exit ! Save configuration CoreSwitch-01(config)# exit CoreSwitch-01# copy running-config startup-config

Switch Advantages Over Hubs

Microsegmentation: Each port creates a separate collision domain, eliminating collisions and providing dedicated bandwidth.

Full-Duplex Operation: Simultaneous send and receive capabilities double the effective bandwidth.

MAC Address Learning: Intelligent frame forwarding reduces unnecessary network traffic.

Enhanced Security: Unicast traffic is sent only to the intended recipient port.

Router Configuration Example

Basic router setup for connecting multiple networks with NAT:

! Configure WAN interface Router(config)# interface gigabitethernet 0/0 Router(config-if)# description "WAN Connection to ISP" Router(config-if)# ip address dhcp Router(config-if)# no shutdown ! Configure LAN interface Router(config)# interface gigabitethernet 0/1 Router(config-if)# description "LAN Connection" Router(config-if)# ip address 192.168.1.1 255.255.255.0 Router(config-if)# no shutdown ! Configure static default route Router(config)# ip route 0.0.0.0 0.0.0.0 gigabitethernet 0/0 ! Enable NAT for internet access Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255 Router(config)# ip nat inside source list 1 interface g0/0 overload Router(config)# interface g0/1 Router(config-if)# ip nat inside Router(config)# interface g0/0 Router(config-if)# ip nat outside

802.1Q Trunking

IEEE 802.1Q standard enables multiple VLANs to traverse a single physical link by adding VLAN tags to Ethernet frames.

Port Type VLAN Support Frame Tagging Typical Use
Access Port Single VLAN only Untagged frames End devices (PCs, phones)

VLAN Configuration

Complete VLAN setup including creation, access ports, and trunk configuration:

! Create VLANs Switch(config)# vlan 10 Switch(config-vlan)# name Sales-Department Switch(config-vlan)# exit Switch(config)# vlan 20 Switch(config-vlan)# name Engineering-Department Switch(config-vlan)# exit Switch(config)# vlan 99 Switch(config-vlan)# name Management-Network Switch(config-vlan)# exit ! Configure access ports Switch(config)# interface range fastethernet 0/1-10 Switch(config-if-range)# switchport mode access Switch(config-if-range)# switchport access vlan 10 Switch(config)# interface range fastethernet 0/11-20 Switch(config-if-range)# switchport mode access Switch(config-if-range)# switchport access vlan 20 ! Configure trunk port Switch(config)# interface gigabitethernet 0/1 Switch(config-if)# switchport mode trunk Switch(config-if)# switchport trunk allowed vlan 10,20,99 Switch(config-if)# switchport trunk native vlan 99

VLAN Security Considerations

Native VLAN Security: Change from default VLAN 1 to prevent VLAN hopping attacks. Mismatched native VLANs can create security vulnerabilities.

Trunk Security: Explicitly define allowed VLANs on trunk ports and use VLAN pruning to remove unnecessary VLANs from trunk links.

Wireless Security Configuration

Essential security settings for enterprise wireless deployments:

  • WPA3-Enterprise: Strongest encryption with 802.1X authentication and RADIUS integration
  • SSID Management: Descriptive names, disable broadcast for hidden networks if required
  • MAC Filtering: Additional access control (security through obscurity)
  • Guest Networks: Isolated network segments for visitor access
  • Channel Planning: Non-overlapping channels (1, 6, 11 for 2.4GHz)
  • Power Management: Optimize signal coverage and reduce interference

Enterprise Wireless Deployment

Site Survey: Conduct RF analysis to determine optimal AP placement, channel assignment, and power levels.

Controller-Based Architecture: Use wireless controllers for centralized management, seamless roaming, and consistent policy enforcement across multiple access points.
