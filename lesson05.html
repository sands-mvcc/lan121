Network Operations I — Core Network Services

Domains 1 and 2 built the roads; Domain 3 runs the traffic. This lesson covers the invisible services every network depends on: ARP, which turns IP addresses into MAC addresses; DNS in depth — the resolution hierarchy, record types, zones, and the modern security additions DNSSEC, DoH, and DoT; DHCP scopes, reservations, exclusions, leases, relay, and IPv6's SLAAC; the time services NTP, PTP, and NTS that keep logs, certificates, and authentication honest; ICMP, the network's diagnostic voice behind ping and traceroute; and IPAM plus the web and mail services users actually see. Seven interactive simulators are woven into the sections — work each one as you reach it.

Key Terms & Concepts

🔎ARPTAP TO FLIP
Address Resolution Protocol — broadcasts "who has this IP?" and caches the MAC address that answers. The bridge between Layer 3 addressing and Layer 2 delivery.
🩺ICMPTAP TO FLIP
Internet Control Message Protocol — the network's error and diagnostic messenger: echo request/reply (ping), TTL exceeded (traceroute), destination unreachable.
📇A / AAAA RecordsTAP TO FLIP
The address records: A maps a hostname to an IPv4 address; AAAA ("quad-A") maps it to an IPv6 address. The workhorses of DNS.
🏷️CNAME RecordTAP TO FLIP
Canonical Name — an alias pointing one hostname at another (www → webserver01.mvcc.edu). The alias inherits wherever the target points.
📮MX RecordTAP TO FLIP
Mail Exchange — names the server(s) that accept email for a domain, each with a preference number (lowest = tried first).
🕵️Recursive ResolverTAP TO FLIP
The DNS server that does the legwork for clients — querying root, TLD, and authoritative servers, then caching the answer. Usually your ISP's or 8.8.8.8/1.1.1.1.
⚖️Authoritative ServerTAP TO FLIP
The DNS server that OWNS the zone's records and gives the final, official answer for its domain — no guessing, no forwarding.
✍️DNSSECTAP TO FLIP
DNS Security Extensions — digitally signs DNS records so resolvers can verify they're authentic and untampered. Protects integrity, not privacy.
🔐DoH / DoTTAP TO FLIP
DNS over HTTPS (port 443, hides inside web traffic) and DNS over TLS (dedicated port 853) — both encrypt queries between client and resolver. Privacy, not authenticity.
🎯DHCP ScopeTAP TO FLIP
The pool of addresses a DHCP server may lease on one subnet, plus its options: default gateway, DNS servers, lease time.
🪑ReservationTAP TO FLIP
A scope entry that always hands a specific MAC address the same IP — DHCP's convenience with static predictability. Perfect for printers and cameras.
⏳LeaseTAP TO FLIP
The time a client may keep its DHCP address. Clients try to renew at 50% of the lease (T1) with the original server, and rebind at 87.5% (T2) with any server.
📨DHCP RelayTAP TO FLIP
A router function (IP helper address) that converts a client's local DHCP broadcast into a unicast aimed at a central DHCP server on another subnet.
🪄SLAACTAP TO FLIP
Stateless Address Autoconfiguration — an IPv6 host builds its own address from the router-advertised prefix plus a self-generated interface ID. No server, no lease.
🗼NTP StratumTAP TO FLIP
Distance from the reference clock: stratum 0 = the atomic/GPS clock itself, stratum 1 = servers attached to it, stratum 2 syncs from stratum 1, and so on.
⚡PTPTAP TO FLIP
Precision Time Protocol (IEEE 1588) — hardware-timestamped sync to sub-microsecond accuracy for trading floors, broadcast, and industrial control. NTP's precise sibling.
🛡️NTSTAP TO FLIP
Network Time Security — adds TLS-based authentication to NTP so a spoofed server can't shift your clocks (and silently break certificates and logs).
🗃️IPAMTAP TO FLIP
IP Address Management — software that tracks every subnet, scope, lease, and DNS record in one place, replacing the infamous spreadsheet.

Lesson Content

An IP address gets a packet to the right network; a MAC address gets the frame to the right machine. When a host knows a destination IP on its own subnet but not the MAC, it uses the Address Resolution Protocol: it broadcasts an ARP request — "Who has 192.168.1.20? Tell 192.168.1.10" — to FF:FF:FF:FF:FF:FF. Every host hears it; only the owner answers with a unicast reply carrying its MAC. The asker stores the pair in its ARP cache for a few minutes so the question isn't repeated for every frame.

  • View the cache: arp -a on Windows/macOS/Linux shows learned IP↔MAC pairs and whether each was dynamic or static.
  • Off-subnet destinations: the host ARPs for its default gateway's MAC instead — Layer 2 only ever delivers to the next hop.
  • Gratuitous ARP: an unsolicited announcement of your own IP→MAC — used when interfaces come up and by FHRP failovers (Lesson 4) to update everyone's cache instantly.
  • IPv6: ARP doesn't exist there — Neighbor Discovery (NDP over ICMPv6) does the same job with multicast instead of broadcast.

The Domain Name System is a distributed, hierarchical database that turns names into addresses. No single server knows everything; instead, each layer knows who to ask next.

Recursive vs. authoritative — who does the work

Your laptop's stub resolver asks one question of a recursive resolver (campus DNS, 8.8.8.8, 1.1.1.1) and waits. The recursive resolver does the walking: it asks a root server (which delegates to .edu), the TLD server (which delegates to mvcc.edu's name servers), and finally the authoritative server that owns the zone and gives the official answer. The resolver caches the result for the record's TTL so the next student's lookup is instant.

Zone types

A zone is the slice of the namespace a server is authoritative for. Forward zones answer name→address; reverse zones answer address→name (PTR). A primary zone holds the writable copy; secondary zones pull read-only copies via zone transfer, triggered when the SOA serial number increments.

The vocabulary of a scope

  • Scope — the address pool for one subnet, plus options: default gateway (option 3), DNS servers (option 6), domain name, lease time.
  • Exclusion — addresses inside the range the server must never lease (your statically addressed router, servers, printers).
  • Reservation — a MAC address that always receives the same IP. Central control with static predictability.
  • Lease time — how long the address is good. Clients renew at 50% of the lease (T1, unicast to their server) and rebind at 87.5% (T2, broadcast to any server). Short leases suit guest Wi-Fi; long leases suit stable offices.

DHCP relay — one server, many subnets

DISCOVER is a broadcast, and routers don't forward broadcasts. Rather than one DHCP server per subnet, configure the router interface as a DHCP relay with a helper address (ip helper-address 10.1.1.5): it repackages the client's broadcast as a unicast to the central server, stamping in the subnet it came from so the server picks the right scope.

SLAAC — how IPv6 does it without a server

An IPv6 host listens for the router's Router Advertisement, takes the advertised /64 prefix, appends a self-generated interface ID, checks for duplicates, and starts talking — Stateless Address Autoconfiguration. No server, no lease, no table of who has what (that statelessness is why enterprises often still layer DHCPv6 on top for logging and options).

Wrong clocks break things quietly: log timestamps stop lining up across devices (good luck correlating an incident), Kerberos authentication rejects tickets, and TLS certificates appear expired or not-yet-valid. Time is infrastructure.

NTP and the stratum hierarchy

Network Time Protocol (UDP 123) syncs clocks across a hierarchy measured in stratum levels — distance from the reference clock, not quality of hardware:

  • PTP (Precision Time Protocol, IEEE 1588) — when milliseconds aren't good enough. Hardware timestamping in the NICs and switches delivers sub-microsecond sync for financial trading, broadcast studios, and industrial control.
  • NTS (Network Time Security) — plain NTP is unauthenticated; an attacker who can spoof it can roll your clocks and break certificate validation and log integrity. NTS adds TLS-based key exchange so clients verify the time source.

The Internet Control Message Protocol carries no user data — it carries news about the network. Two message pairs matter most:

  • Echo Request / Echo Reply — the heartbeat behind ping. Reply received = the destination is reachable, and round-trip time tells you how far/slow.
  • Time Exceeded — a router discarding a packet whose TTL hit zero reports back. traceroute weaponizes this: it sends probes with TTL=1, 2, 3… and each hop's "time exceeded" message reveals that router's address, mapping the path one hop at a time.
  • Destination Unreachable — the network's precise complaint, with a code that matters: network unreachable (no route), host unreachable (route ok, host doesn't answer ARP), port unreachable (host up, service down).

IPv6 promotes ICMP from helpful to essential: ICMPv6 carries Neighbor Discovery (ARP's replacement), Router Advertisements (SLAAC, Section 3), and path MTU discovery — block it entirely and IPv6 breaks.

💡Field habit: ping the loopback (127.0.0.1) → your stack works; ping your gateway → the LAN works; ping 8.8.8.8 → routing works; ping google.com → DNS works. Four pings, and you've isolated the failing layer.

IPAM — retiring the spreadsheet

Every organization eventually asks: who has 10.4.7.22, and is 10.8.0.0/16 free? IP Address Management software answers authoritatively by integrating three views — the subnet plan, live DHCP scopes and leases, and DNS records (the trio is often sold together as DDI: DNS-DHCP-IPAM). Good IPAM tracks utilization, flags conflicts and overlapping subnets, and gives auditors the "who had this address when" answer that a stale spreadsheet never can.

Web services — HTTP & HTTPS

HTTP (TCP 80) is the web's request/response protocol; HTTPS (TCP 443) wraps it in TLS, providing encryption, integrity, and server authentication via certificates — which is why accurate time (Section 4) and honest DNS (Section 2) both feed directly into whether that padlock appears. Modern sites are HTTPS-only; port 80's remaining job is redirecting to 443.

Knowledge Check

Q1. How does a host learn the MAC address for an IP on its own subnet?
Rationale: ARP: the request goes to FF:FF:FF:FF:FF:FF so everyone hears it; only the IP's owner answers, unicast, and the mapping is cached.
Q2. Which DNS server ultimately provides the official answer for records in the mvcc.edu zone?
Rationale: Root and TLD servers only delegate ("ask them next"); the recursive resolver just does the walking and caching. Authority lives with the server that owns the zone.
Q3. Mail for @mvcc.edu must be delivered to a new server. Which record do you update?
Rationale: MX records name a domain's mail servers (with preference numbers — lowest wins). CNAME aliases, PTR reverses, SOA holds zone metadata.
Q4. A company wants DNS queries encrypted on a dedicated, easily identifiable port. Which technology and port?
Rationale: DNS over TLS uses dedicated port 853 — visible and manageable. DoH (443) hides inside web traffic; DNSSEC signs records for authenticity but encrypts nothing.
Q5. Clients on VLAN 30 can't get addresses; the only DHCP server sits on VLAN 10. The fix?
Rationale: DISCOVER is a broadcast and routers don't forward broadcasts. A relay (ip helper-address) converts it to unicast aimed at the central server, tagging the source subnet so the right scope answers.
Q6. By default, when does a DHCP client first attempt to renew its lease?
Rationale: T1 renewal fires at 50%, quietly, to the server that granted the lease. Only if that fails does the client rebind at 87.5% (T2) via broadcast — and fall back to APIPA if everything fails.
Q7. A trading firm needs clocks synchronized to sub-microsecond accuracy across its network. Which protocol fits?
Rationale: Precision Time Protocol (IEEE 1588) uses hardware timestamping for sub-microsecond sync. NTP is millisecond-class; NTS secures NTP but doesn't sharpen it.
Q8. How does an IPv6 host using SLAAC obtain its address?
Rationale: SLAAC is stateless: Router Advertisement supplies the /64 prefix, the host generates its own interface ID, verifies uniqueness, and is done — no server, no lease table.
