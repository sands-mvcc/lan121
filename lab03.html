Split one network into three, then route between them

Ridgeview Supply's office runs on one flat network. You'll segment it into Sales, Engineering, and HR VLANs across three Cisco 2960 switches, then configure a Cisco 4321 router so the departments can still reach each other. Every command runs in a simulated IOS console, and every result shows up live on the network map.

What you should know

  • A VLAN is a separate broadcast domain on shared switch hardware, and each VLAN normally gets its own IP subnet.
  • Access ports carry one VLAN to an end device; trunk ports carry many VLANs between switches and routers using 802.1Q tags.
  • Devices in different VLANs can't talk without a Layer 3 device. A router (or multilayer switch) must route between them.
  • Router-on-a-stick uses one physical router link split into subinterfaces, one per VLAN, each acting as that VLAN's default gateway.
  • Connected routes appear in the routing table automatically when an interface with an IP address is up.
  • Every switch along the path must know the VLAN, and every trunk must allow it.

What you'll be able to do

  • Move between IOS modes: user EXEC, privileged EXEC, global config, interface, and VLAN.
  • Create and name VLANs and assign switch ports to them in access mode.
  • Configure static 802.1Q trunks between switches and to a router.
  • Enable a router interface and build dot1Q subinterfaces with gateway addresses.
  • Verify with show vlan brief, show interfaces trunk, show ip interface brief, and show ip route.
  • Test reachability within and between VLANs and troubleshoot what fails.

The commands you'll use

Work through these in order. They follow the same sequence as the lab. IOS accepts abbreviations, so conf t, int f0/1, and sh vl br all work in the console.

1Move between IOS modesWhere you are determines what you can type
Switch>enableSwitch#configure terminalSwitch(config)#interface f0/1Switch(config-if)#
Switch> enable ! user EXEC to privileged EXEC Switch# configure terminal ! enter global configuration Switch(config)# hostname SW1 SW1(config)# exit ! back one level SW1# ! end or Ctrl+Z jumps straight here

Show commands run from privileged EXEC. Inside configuration modes, put do in front: do show vlan brief.

2Create and name VLANsRun on every switch that will carry the VLAN
SW1(config)# vlan 10 SW1(config-vlan)# name SALES SW1(config-vlan)# vlan 20 SW1(config-vlan)# name ENGINEERING SW1(config-vlan)# vlan 30 SW1(config-vlan)# name HR SW1(config-vlan)# end
SW1 has no PCs, but it still needs all three VLANs. A switch drops frames for any VLAN missing from its VLAN database, even when they arrive on a trunk. Without VTP, you create VLANs on each switch by hand.
3Assign access portsOne VLAN per end-device port
SW2(config)# interface fastethernet0/1 SW2(config-if)# switchport mode access ! never negotiate a trunk SW2(config-if)# switchport access vlan 10 SW2(config-if)# interface f0/2 SW2(config-if)# switchport mode access SW2(config-if)# switchport access vlan 20

For several ports at once, use interface range f0/1 - 2. If you assign a VLAN that doesn't exist yet, the switch creates it with a placeholder name like VLAN0010, so you still need to name it.

4Configure trunksSwitch-to-switch and switch-to-router links
SW1(config)# interface range g0/1, f0/23 - 24 SW1(config-if-range)# switchport mode trunk SW1(config-if-range)# switchport trunk allowed vlan 10,20,30 ! optional hardening

Configure the other end too (F0/24 on SW2 and SW3). A 2960 port defaults to dynamic auto, and two auto ports never form a trunk. Setting both ends to trunk removes the guesswork.

The link to the router must be a static trunk on the switch side. Routers don't negotiate trunks with DTP.
5Build router-on-a-stickOne physical link, one subinterface per VLAN
R1(config)# interface g0/0/0 R1(config-if)# no shutdown ! router ports start shut down R1(config-if)# interface g0/0/0.10 R1(config-subif)# encapsulation dot1Q 10 ! must come before the IP R1(config-subif)# ip address 192.168.10.1 255.255.255.0 R1(config-subif)# interface g0/0/0.20 R1(config-subif)# encapsulation dot1Q 20 R1(config-subif)# ip address 192.168.20.1 255.255.255.0

The subinterface number (.10) is just a label. The encapsulation dot1Q 10 line is what ties it to VLAN 10. Matching them keeps the config readable.

6VerifyProve the configuration before you test traffic
SW2# show vlan brief ! VLAN names and access port membership SW1# show interfaces trunk ! which ports trunk and which VLANs they carry SW2# show interfaces f0/1 switchport ! one port's mode and VLAN R1# show ip interface brief ! interface status and addresses R1# show ip route ! connected (C) and local (L) routes R1# ping 192.168.10.11

Trunk ports never appear in show vlan brief. If a port you expect to see is missing, it's probably trunking.
