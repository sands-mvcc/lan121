Domain 5: Network Troubleshooting

Essential troubleshooting skills for network professionals

Domain Overview

This domain covers the essential troubleshooting skills needed by network professionals. You'll learn systematic approaches to diagnose and resolve network issues across all layers of the OSI model.

Weight on Exam: 24% of total exam

What You'll Master:

  • Systematic troubleshooting methodology
  • Physical layer issue identification and resolution
  • Network service troubleshooting techniques
  • Performance problem diagnosis
  • Appropriate tool selection and usage

OSI Model Reference

Layer 7 - Application: User applications, email, web browsers
Layer 6 - Presentation: Data encryption, compression, formatting
Layer 5 - Session: Session management, connections
Layer 4 - Transport: TCP/UDP, ports, flow control
Layer 3 - Network: IP addressing, routing, ICMP
Layer 2 - Data Link: Switching, VLANs, MAC addresses
Layer 1 - Physical: Cables, connectors, electrical signals

Domain 5 Learning Objectives

CompTIA Network+ N10-009 Exam Requirements

Troubleshooting Methodology

Systematic approach to network problem solving

7-Step Troubleshooting Process

1 Identify the Problem
  • Gather information from users and systems
  • Question users about symptoms and changes
  • Identify specific symptoms
  • Determine if anything has changed recently
  • Duplicate the problem if possible
  • Approach multiple problems individually
2 Establish a Theory of Probable Cause
  • Question the obvious first
  • Consider multiple approaches (Top-down, Bottom-up, Divide and conquer)
  • Use experience and knowledge to form hypotheses
3 Test the Theory
  • If theory is confirmed, determine next steps
  • If theory is not confirmed, establish new theory or escalate
4 Establish a Plan of Action
  • Develop solution steps
  • Identify potential effects of changes
  • Consider rollback procedures
5 Implement the Solution
  • Execute planned changes
  • Escalate if necessary
  • Monitor implementation progress
6 Verify Full System Functionality
  • Test affected systems thoroughly
  • Implement preventive measures if applicable
  • Ensure no new issues were created
7 Document Findings
  • Record findings, actions, and outcomes
  • Document lessons learned
  • Update knowledge base for future reference

Troubleshooting Approaches

Top-Down Approach

Start: Application Layer (7) → Direction: Down to Physical (1)

Best for: Application-related issues, software problems

Example: User can't access website → Check browser → Check network settings → Check physical connection

Bottom-Up Approach

Start: Physical Layer (1) → Direction: Up to Application (7)

Best for: Hardware issues, widespread outages

Example: Network down → Check cables → Check switches → Check routing → Check services

Divide and Conquer

Start: Network Layer (3) → Direction: Up or down based on results

Best for: Unknown issues, general troubleshooting

Example: Start with ping test → If successful, go up; if failed, go down

Layer 1 (Physical) Issues

Cabling and physical interface troubleshooting

Cable Issues

Incorrect Cable Types

  • Single mode vs. multimode fiber: Distance and equipment compatibility
  • Category cables: Cat 5/6/7/8 speed and distance limitations
  • STP vs. UTP: Electromagnetic interference considerations

Signal Degradation

  • Crosstalk: Signal interference between cable pairs
  • Interference: EMI from external sources
  • Attenuation: Signal loss over distance

Termination Problems

  • Improper termination: Incorrect wiring standards (T568A/T568B)
  • TX/RX transposed: Transmit and receive pairs swapped

Interface Issues

Interface Counters

  • CRC errors: Cyclic redundancy check failures
  • Runts: Frames smaller than 64 bytes
  • Giants: Frames larger than 1518 bytes
  • Drops: Frames discarded due to buffer overflow

Port Status Issues

  • Error disabled: Port automatically shut down due to errors
  • Administratively down: Port manually disabled
  • Suspended: Port temporarily disabled

Hardware Issues

Power over Ethernet (PoE)

  • Power budget exceeded: Insufficient power supply capacity
  • Incorrect standard: PoE/PoE+/PoE++ compatibility issues

Transceiver Issues

  • Mismatch: Incompatible transceiver types or speeds
  • Signal strength: Insufficient optical power levels

Software Troubleshooting Tools

Command line and protocol analysis tools

Protocol Analyzers

Packet Capture Tools

  • Wireshark: Full-featured protocol analyzer with GUI
  • tcpdump: Command-line packet analyzer
  • Network taps: Hardware devices for packet capture

Command Line Tools

Connectivity Testing

  • ping: Test reachability using ICMP echo requests
  • traceroute/tracert: Display route packets take to destination
  • pathping: Windows tool combining ping and tracert

DNS Resolution

  • nslookup: Query DNS servers for name resolution
  • dig: Flexible DNS lookup tool (Linux/Unix)

Network Configuration

  • ipconfig: Windows IP configuration utility
  • ifconfig: Unix/Linux interface configuration
  • ip: Modern Linux networking tool
  • netstat: Display network connections and statistics
  • arp: Display and modify ARP cache

Discovery Tools

Network Mapping

  • Nmap: Network discovery and security scanning
  • LLDP: Link Layer Discovery Protocol
  • CDP: Cisco Discovery Protocol

Performance Testing

  • Speed testers: Bandwidth measurement tools
  • iPerf: Network performance measurement

Wireless Troubleshooting

Common wireless network problems and solutions

Interference Issues

Channel Overlap

  • Adjacent channel interference in 2.4GHz band
  • Use non-overlapping channels (1, 6, 11)
  • Consider 5GHz for more available channels

Signal Interference

  • Physical obstacles: Walls, metal structures
  • Electronic devices: Microwaves, Bluetooth devices
  • Other wireless networks: Neighboring access points

Coverage and Signal Issues

Signal Degradation or Loss

  • Distance from access point
  • Physical obstructions
  • Antenna positioning and type

Insufficient Wireless Coverage

  • Dead zones in coverage area
  • Need for additional access points
  • Proper site survey requirements

Client and Roaming Issues

Client Disassociation

  • Power management settings
  • Signal strength thresholds
  • Authentication timeouts

Roaming Misconfiguration

  • Incorrect roaming thresholds
  • SSID and security mismatches
  • 802.11r fast roaming configuration

General Network Issues

Service and performance troubleshooting

Switching Issues

Spanning Tree Protocol (STP)

  • Network loops: Broadcast storms and network instability
  • Root bridge selection: Improper root bridge placement
  • Port roles: Designated, root, and blocked port issues
  • Port states: Learning, listening, forwarding states

VLAN Issues

  • Incorrect VLAN assignment: Ports in wrong VLANs
  • Trunking problems: Native VLAN mismatches
  • Inter-VLAN routing: Layer 3 connectivity issues

Access Control Lists (ACLs)

  • Incorrect rule order: More specific rules after general ones
  • Implicit deny: Traffic blocked by default deny rule
  • Misconfigured permissions: Allow/deny rule conflicts

Routing Issues

Route Selection Problems

  • Routing table issues: Missing or incorrect routes
  • Default routes: Missing or incorrect default gateway
  • Metric problems: Suboptimal path selection

Address Configuration

  • Address pool exhaustion: DHCP scope full
  • Incorrect default gateway: Wrong router address
  • Duplicate IP addresses: Address conflicts
  • Incorrect subnet mask: Wrong network boundaries

Performance Issues

Bandwidth and Throughput

  • Congestion/contention: Too much traffic for available bandwidth
  • Bottlenecking: Single point limiting overall performance
  • Throughput capacity: Actual vs. theoretical bandwidth

Quality of Service Issues

  • Latency: Delays in packet transmission
  • Packet loss: Dropped packets due to congestion
  • Jitter: Variation in packet arrival times

Task Assessments

Test your Domain 5 troubleshooting knowledge

Network+ Domain 5 Assessment Questions

Complete these 10 questions to test your understanding of network troubleshooting concepts.

Question 1

According to the CompTIA troubleshooting methodology, what is the first step when approaching a network problem?

A) Establish a theory of probable cause
B) Identify the problem
C) Test the theory to determine the cause
D) Implement the solution
Correct Answer: B) Identify the problem
The first step in the 7-step troubleshooting methodology is to identify the problem by gathering information, questioning users, and identifying symptoms.
Question 2

A network technician notices increasing CRC errors on a switch port. What layer of the OSI model is most likely experiencing issues?

A) Physical Layer (Layer 1)
B) Data Link Layer (Layer 2)
C) Network Layer (Layer 3)
D) Transport Layer (Layer 4)
Correct Answer: A) Physical Layer (Layer 1)
CRC (Cyclic Redundancy Check) errors typically indicate physical layer problems such as bad cables, connectors, or signal degradation.
Question 3

Which troubleshooting approach should be used when users report they cannot access a specific web application, but other network services work fine?

A) Bottom-up approach
B) Top-down approach
C) Divide and conquer
D) Replace all cables first
Correct Answer: B) Top-down approach
Since the issue is application-specific and other network services work, start at the Application layer and work down to isolate the problem.
Question 4

A technician is troubleshooting intermittent wireless connectivity issues. Which tool would be MOST appropriate for identifying channel interference?

A) Cable tester
B) Wi-Fi analyzer
C) Toner probe
D) Loopback plug
Correct Answer: B) Wi-Fi analyzer
A Wi-Fi analyzer can detect channel usage, interference sources, and signal strength issues in wireless networks.
Question 5

What command would you use to display the path packets take from source to destination and identify where delays occur?

A) ping
B) netstat
C) traceroute
D) nslookup
Correct Answer: C) traceroute
Traceroute (or tracert on Windows) shows the path packets take through the network and can identify where delays or failures occur.
Question 6

A switch port is showing "error disabled" status. What is the most likely cause?

A) Port was manually shut down by administrator
B) Port automatically shut down due to security violation or errors
C) Port is in spanning tree learning state
D) Port speed mismatch with connected device
Correct Answer: B) Port automatically shut down due to security violation or errors
"Error disabled" means the port was automatically disabled by the switch due to conditions like port security violations, excessive errors, or STP issues.
Question 7

Users are experiencing slow network performance during peak hours. Which performance issue is most likely occurring?

A) Jitter
B) Congestion
C) Crosstalk
D) Attenuation
Correct Answer: B) Congestion
Congestion occurs when network demand exceeds available bandwidth capacity, typically during peak usage times.
Question 8

A network has DHCP scope exhaustion. What is the immediate solution to allow new devices to connect?

A) Restart the DHCP server
B) Increase the DHCP lease time
C) Expand the DHCP scope or add additional scope
D) Enable DHCP relay
Correct Answer: C) Expand the DHCP scope or add additional scope
Address pool exhaustion means all available IP addresses in the scope are assigned. Adding more addresses to the scope resolves this immediately.
Question 9

Which type of cable issue would cause TX/RX transposed problems?

A) Signal attenuation
B) Electromagnetic interference
C) Improper termination
D) Cable length exceeded
Correct Answer: C) Improper termination
TX/RX transposed means transmit and receive pairs are swapped, which is caused by incorrect wiring during cable termination.
Question 10

A wireless client keeps disconnecting from the access point when moving between conference rooms. What is the most likely cause?

A) Channel interference
B) Roaming misconfiguration
C) Insufficient wireless coverage
D) Wrong encryption protocol
Correct Answer: B) Roaming misconfiguration
When clients disconnect while moving between areas served by different access points, it typically indicates roaming configuration issues.
