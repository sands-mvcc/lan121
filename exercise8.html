🎯 Domain 5 Learning Objectives

This domain covers the essential troubleshooting skills needed by network professionals. You'll learn systematic approaches to diagnose and resolve network issues across all layers of the OSI model.

Layer 7 - Application: User applications, email, web browsers
Layer 6 - Presentation: Data encryption, compression, formatting

🔧 Troubleshooting Methodology

Systematic approach to identifying and resolving network problems

📋 The 7-Step Troubleshooting Process

1 Identify the Problem
  • Gather information from users and systems
  • Question users about symptoms
  • Identify what has changed recently
  • Duplicate the problem if possible
  • Approach multiple problems individually
2 Establish a Theory of Probable Cause
  • Question the obvious
  • Consider multiple approaches
  • Use top-to-bottom/bottom-to-top OSI model
  • Apply divide and conquer methodology
3 Test the Theory
  • If confirmed, determine next steps
  • If not confirmed, establish new theory
  • Escalate if necessary
4 Establish Plan of Action
  • Identify potential effects
  • Consider impact on users
  • Plan for rollback if needed
5 Implement Solution
  • Execute the plan
  • Escalate if implementation fails
  • Monitor for unexpected issues
6 Verify Full System Functionality
  • Test all affected systems
  • Implement preventive measures
  • Ensure no new issues were created
7 Document Everything
  • Document findings and actions
  • Record outcomes and lessons learned
  • Update knowledge base

🌐 General Network Issues

Performance, connectivity, and service-related problems

🐌 Performance Issues

Bandwidth Problems

  • Congestion: Network overutilization
  • Bottlenecking: Single point of congestion
  • Throughput Capacity: Maximum data transfer rate
  • Contention: Multiple devices competing

Latency and Delay

  • High Latency: Slow response times
  • Jitter: Variable delay in packets
  • Packet Loss: Dropped packets in transit
  • Processing Delay: Device processing time

Quality of Service (QoS)

  • Traffic Prioritization: Critical traffic first
  • Bandwidth Allocation: Guaranteed minimums
  • Queue Management: Buffer optimization
  • Traffic Shaping: Rate limiting

🔗 Connectivity Issues

Switching Problems

  • STP Issues: Network loops, convergence
  • VLAN Misconfigurations: Wrong VLAN assignments
  • Port Security: MAC address violations
  • Duplex Mismatches: Half vs full duplex

Routing Problems

  • Incorrect Routes: Wrong path selection
  • Missing Default Gateway: No route to internet
  • Routing Loops: Circular routing paths
  • Asymmetric Routing: Different paths

IP Addressing Issues

  • Duplicate IP Addresses: IP conflicts
  • Wrong Subnet Mask: Incorrect network boundaries
  • DHCP Pool Exhaustion: No available IPs
  • DNS Problems: Name resolution failures

📝 Task Assessments

Test your knowledge with these 10 comprehensive scenarios

Assessment 1: Troubleshooting Methodology

A user reports that they cannot access the company email server. According to the CompTIA troubleshooting methodology, what should be your FIRST step?

A) Test the theory by pinging the email server
B) Replace the network cable
C) Gather information about the problem and question the user
D) Implement a solution immediately
Correct Answer: C
The first step in the troubleshooting methodology is to identify the problem by gathering information and questioning users about symptoms, recent changes, and the exact nature of the issue.

Assessment 2: Physical Layer Issues

You notice increasing CRC errors on a switch port. What is the MOST likely cause?

A) Incorrect VLAN configuration
B) Physical cable or connector issues
C) Routing table problems
D) DNS server failure
Correct Answer: B
CRC (Cyclic Redundancy Check) errors indicate data corruption during transmission, which is typically caused by physical layer issues such as damaged cables, poor connections, or electromagnetic interference.

Assessment 3: Command Line Tools

Which command would you use to determine the path packets take from your computer to a remote server?

A) ping
B) tracert/traceroute
C) nslookup
D) netstat
Correct Answer: B
Tracert (Windows) or traceroute (Linux/Mac) shows the path packets take through the network, displaying each hop and the round-trip time to reach each router along the path.

Assessment 4: Wireless Troubleshooting

Users in a conference room report slow Wi-Fi performance. A site survey shows multiple access points using channel 6. What is the BEST solution?

A) Change some access points to non-overlapping channels (1 or 11)
B) Increase the transmission power on all access points
C) Move all access points to channel 6
D) Disable WPA2 encryption
Correct Answer: A
In the 2.4GHz band, channels 1, 6, and 11 are non-overlapping. Having multiple APs on the same channel causes co-channel interference, reducing performance. Distributing APs across non-overlapping channels improves performance.

Assessment 5: Network Performance

Users report intermittent slow network performance. Network monitoring shows high jitter values. What does this indicate?

A) Complete network failure
B) Variable delay in packet delivery
C) DNS resolution problems
D) Physical layer cable issues
Correct Answer: B
Jitter refers to the variation in packet delay. High jitter means packets are arriving at inconsistent intervals, which can cause performance issues, especially for real-time applications like VoIP and video conferencing.

Assessment 6: Switching Issues

A network experiences a broadcast storm that brings down the entire LAN. What spanning tree protocol issue is MOST likely the cause?

A) A network loop due to STP failure or misconfiguration
B) Incorrect VLAN assignment
C) Port security violation
D) Duplex mismatch
Correct Answer: A
Broadcast storms typically occur when there's a network loop. STP (Spanning Tree Protocol) is designed to prevent loops, so if STP fails or is misconfigured, loops can form and cause broadcast storms that flood the network with traffic.

Assessment 7: OSI Model Troubleshooting

You can successfully ping a web server by IP address but cannot access it using the domain name. Which OSI layer should you focus on?

A) Physical Layer (Layer 1)
B) Data Link Layer (Layer 2)
C) Network Layer (Layer 3)
D) Application Layer (Layer 7) - DNS issues
Correct Answer: D
Since ping by IP works, layers 1-3 are functioning correctly. The issue is with name resolution (DNS), which operates at the Application Layer. Check DNS server configuration and connectivity.

Assessment 8: Hardware Tools

You suspect a cable may be damaged but it's installed in walls and difficult to access. Which tool would be MOST helpful for locating the cable?

A) Toner and probe
B) Protocol analyzer
C) Spectrum analyzer
D) Cable tester
Correct Answer: A
A toner and probe (also called a fox and hound) allows you to trace cables through walls and other hidden areas. The toner sends a signal down the cable, and the probe detects the signal to help locate and identify the specific cable.

Assessment 9: DHCP Issues

Several users receive APIPA addresses (169.254.x.x). What is the MOST likely cause?

A) DNS server failure
B) DHCP server unavailable or pool exhausted
C) Routing table corruption
D) Physical cable damage
Correct Answer: B
APIPA (Automatic Private IP Addressing) addresses are self-assigned when a device cannot obtain an IP address from a DHCP server. This typically indicates the DHCP server is unreachable or has no available IP addresses in its pool.

Assessment 10: Comprehensive Scenario

A company's network is experiencing intermittent connectivity issues. Users can connect sometimes but not others. The issue affects multiple VLANs. Network monitoring shows high CPU usage on the core switch during outages. What troubleshooting approach should you take?

A) Replace all network cables immediately
B) Use divide-and-conquer: check switch performance, then investigate high CPU usage causes
C) Start with top-down approach from application layer
D) Focus only on VLAN configuration issues
Correct Answer: B
Given the intermittent nature affecting multiple VLANs and high CPU usage correlation, a divide-and-conquer approach starting with the core switch performance makes sense. High CPU could indicate spanning tree convergence issues, broadcast storms, or hardware problems.

Top-Down Approach

Start: Application Layer (7)

Direction: Down to Physical (1)

Best for: Application-related issues, software problems

Example: User can't access website → Check browser → Check network settings → Check physical connection

Bottom-Up Approach

Start: Physical Layer (1)

Direction: Up to Application (7)

Best for: Hardware issues, widespread outages

Example: Network down → Check cables → Check switches → Check routing → Check services

Divide and Conquer

Start: Network Layer (3)

Direction: Up or down based on results

Best for: Unknown issues, general troubleshooting

Example: Start with ping test → If successful, go up; if failed, go down

🔌 Layer 1: Physical Layer Issues

Cabling, connectors, and physical interface troubleshooting

🔗 Cable Issues

Incorrect Cable Types

  • Single-mode vs Multimode Fiber: Distance and bandwidth requirements
  • Cat5/6/7/8: Speed and frequency capabilities
  • STP vs UTP: Shielding requirements
  • Crossover vs Straight-through: Connection requirements

Signal Degradation

  • Crosstalk: Signal interference between cables
  • Attenuation: Signal loss over distance
  • Interference: EMI/RFI from external sources
  • Impedance mismatch: Reflection and signal loss

Termination Issues

  • Improper crimping: Poor connections
  • Wrong pin assignments: T568A vs T568B
  • TX/RX transposed: Incorrect transmit/receive pairing
  • Damaged connectors: Physical connector problems

🔧 Interface and Hardware Issues

Interface Counters

  • CRC Errors: Cyclic redundancy check failures
  • Runts: Frames smaller than 64 bytes
  • Giants: Frames larger than maximum size
  • Drops: Packets dropped due to buffer overflow

Port Status Issues

  • Error Disabled: Port shut down due to errors
  • Administratively Down: Port manually disabled
  • Suspended: Port temporarily disabled
  • Link Down: No physical connection detected

Power Over Ethernet (PoE)

  • Power Budget Exceeded: Insufficient power available
  • Incorrect Standard: PoE vs PoE+ vs PoE++
  • Cable Limitations: Power delivery over distance
  • Device Compatibility: Power requirements mismatch

💻 Software Troubleshooting Tools

Command-line and software tools for network diagnosis

⌨️ Command Line Tools

ping

Purpose: Test basic connectivity using ICMP

Usage: ping [destination]

Key Options: -t (continuous), -n (count), -l (packet size)

traceroute/tracert

Purpose: Show path packets take to destination

Usage: tracert [destination]

Information: Hop-by-hop latency and path

nslookup/dig

Purpose: DNS name resolution testing

Usage: nslookup [domain]

Information: IP addresses, DNS records

netstat

Purpose: Display network connections and statistics

Usage: netstat [options]

Key Options: -a (all), -n (numerical), -r (routing table)

ipconfig/ifconfig

Purpose: Display and configure network interfaces

Usage: ipconfig [options]

Key Options: /all, /release, /renew, /flushdns
