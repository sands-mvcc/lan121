Core knowledge and skills

How DNS works
  • The namespace is a tree: the root (.), top-level domains (.com, .edu, .lan), second-level domains (lakeview.lan), and hosts (www.lakeview.lan).
  • A fully qualified domain name (FQDN) ends with a dot that represents the root. In zone files, that trailing dot decides whether a name is complete or relative.
  • Clients send recursive queries to a resolver; the resolver sends iterative queries to root, TLD, and authoritative servers.
  • Authoritative servers hold the zone data. Caching (recursive) servers look answers up and remember them for the TTL.
  • Forward lookup zones turn names into addresses; reverse lookup zones (in-addr.arpa, ip6.arpa) turn addresses into names.
  • DNS uses UDP port 53 for most queries and TCP port 53 for zone transfers and large responses.
Resource records
  • Know the purpose and syntax of A, AAAA, CNAME, MX, NS, PTR, SOA, TXT, and SRV records.
  • Apply the rules that cause most outages: a CNAME must be alone at its name, MX and NS records point to host names (never IPs), and PTR records live in the reverse zone.
  • Choose sensible TTLs: long for stable records, short before a planned change.
Server configuration
  • Install and enable a DNS service: BIND 9 on Linux or the DNS Server role on Windows Server.
  • Declare zones, create zone files, and increase the SOA serial on every change.
  • Understand primary and secondary servers, zone transfers, and forwarders for outside names.
  • On Windows, know Active Directory–integrated zones, dynamic updates from DHCP clients, and the SRV records domain controllers register.
Testing and troubleshooting
  • Query with dig, nslookup, host, and PowerShell Resolve-DnsName.
  • Validate before reloading with named-checkconf and named-checkzone.
  • Read response codes: NOERROR, NXDOMAIN (name doesn't exist), SERVFAIL (server couldn't answer), REFUSED (server won't answer).
  • Check the client side: ipconfig /all, resolvectl status, /etc/resolv.conf, and clear caches with ipconfig /flushdns.
  • Read service logs with journalctl -u named or the Windows DNS Server event log.
Security and day-to-day operations
  • Restrict zone transfers to known secondary servers; an open transfer hands attackers a map of your network.
  • Allow recursion only for internal clients so your server can't be used in amplification attacks.
  • Recognize split-horizon DNS (different answers inside and outside) and the purpose of DNSSEC.
  • Watch query logs for signs of DNS tunneling or malware beaconing.
  • Follow change control: document every record change and back up zone files.
