Reading the wire

You have 21 seconds of traffic from the campus core switch. Somewhere in it are five attacks hiding among ordinary web, DNS and time traffic. Your job is to find each one, prove it with packet evidence, and write it up the way a network administrator would.

Help desk ticket 4471

Staff on VLAN 10 report web pages that hang, then load. The network management server logged several SNMP authentication failures from the edge router, and the server team saw a short spike of inbound traffic. A capture was taken from the core switch SPAN port, which mirrors both VLANs.

Capture file: mvcc-core-span.pcapng

By the end of this lab you can

  • Navigate a packet capture using display filters, the packet list and the packet details tree.
  • Interpret header fields of IP, TCP, UDP, ICMP, ARP and SNMP and explain what normal looks like.
  • Recognize five attack signatures: ping sweep, SYN scan, SNMP community-string guessing, ARP cache poisoning and UDP flood.
  • Correlate evidence across layers, such as a MAC address to an IP address.
  • Document findings with frame numbers, indicators, severity and a recommended fix.

Procedure

  1. Skim the field guide, especially the header explorer.
  2. Open the capture and complete the warm-up to learn the tools.
  3. Work signatures 1 to 5. Answer each question from the capture, not from memory.
  4. Select a packet that proves each signature and flag it as evidence.
  5. Use Statistics to confirm volume and conversations.
  6. Complete the report, rate severity, recommend a fix, then print or save it as PDF.

Estimated time: 75 to 90 minutes. Each question allows three attempts before the answer is shown for zero points.

Scoring

The report narrative (severity, recommendations, summary) is graded by your instructor.

What a network administrator needs to know

Traffic analysis is part knowledge (what each header field means and what normal looks like) and part skill (finding, correlating and documenting the abnormal). Use this guide while you work.

Knowledge

  • EncapsulationHow Ethernet, IP, TCP or UDP, and the application nest, and which layer each header belongs to.
  • Header fields and normal valuesTTL, flags, ports, ARP opcodes, ICMP type and code, SNMP version and PDU types.
  • Well-known ports21 FTP, 22 SSH, 23 Telnet, 25 SMTP, 53 DNS, 67/68 DHCP, 80 HTTP, 123 NTP, 161/162 SNMP, 443 HTTPS, 445 SMB, 3389 RDP.
  • Connection stateThe TCP three-way handshake, teardown, sequence and acknowledgment numbers, and what a reset means.
  • Layer 2 trustARP has no authentication, so any host can claim any IP-to-MAC mapping.
  • Baselines and signaturesHow sweeps, scans, spoofing, floods and protocol abuse differ from everyday traffic.
  • Capture placement and ethicsSPAN versus TAP, why switches hide traffic, written authorization, privacy and chain of custody.

Skills

  • Capture with intentChoose the capture point and use capture filters (BPF, as in tcpdump) to limit scope.
  • Filter fastWrite display filters that isolate a host, port, flag combination or protocol.
  • Read the details treeExpand each layer and map what you see to the header diagram.
  • CorrelateTie MAC to IP, request to response, and a DNS answer to the session that follows.
  • Use statisticsProtocol hierarchy, conversations and I/O graphs reveal volume anomalies quickly.
  • Reconstruct sessionsFollow a TCP or UDP stream to see the conversation in order.
  • DocumentRecord frame numbers, timestamps, indicators, severity and a recommended control.
